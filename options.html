下载规则

每次开始下载文件时，规则会逐条应用。每 每条规则由若干匹配条件和目标路径模式组成。 匹配条件其实是一组正则表达式， 分别作用于下载项的文件类型、URL、 来源页 URL和文件名。 如果某条规则的所有非空条件都命中， 文件就按该规则的目标路径模式重命名保存，其余规则跳过。

所有正则表达式均不区分大小写。

匹配条件

匹配条件里可以使用任何 正则表达式 语法（包括捕获组）。

MIME 类型

MIME 类型是描述文件格式的字符串。最常见的一些 MIME 类型如下：
application/pdf
PDF 文档
application/zip
压缩包
application/x-bittorrent
BT 种子
application/exe
Windows 可执行文件
audio/mpeg
MP3 等 MPEG 音频
image/gif
GIF 图片
image/jpeg
JPEG 图片
image/png
PNG 图片
video/x-msvideo
AVI 视频

此外还有更详细的 常见 MIME 类型完整列表可供参考。

别忘了可以用通配符匹配一组文件类型（如 image/.* 或 audio/.*）

目标路径模式

这部分定义下载文件的最终存放位置。

可以用占位符引用匹配条件的捕获组， 常用书写格式为： — 格式为 ${matcher:组序号}，其中 matcher matcher 是匹配条件的字段名，num 是捕获组序号 （从 1 开始）。例：占位符 ${referrer:1} 会被替换为 来源页 URL 条件中第 1 个捕获组的内容。
不带序号的占位符（如 ${filename}）则取整个字段。

可用占位符有：mime、url、finalUrl、referrer、filename。

Chrome 会限定最终路径必须位于默认下载文件夹之内， 可用符号链接绕过该限制。

同名冲突处理

文件重名时可选择三种处理方式：

  1. 自动重命名：若文件已存在，会在文件名后追加 "(1)"。 如已存在 "MyImage.jpg"，将保存为 "MyImage (1).jpg"、"MyImage (2).jpg"， 以此类推。
  2. 覆盖：直接覆盖已存在的同名文件。
  3. 询问：弹出对话框逐个确认。

正则速查

"|" 表示"或"。如 facebook|google 可匹配 同时含 facebook 或 google 的任意字符串。
"." 是单字符通配符。如 a.b 能匹配 a-b, acb, a b 等。
".*" 是多字符通配符（可匹配零个字符）
".+" 是多字符通配符（不能匹配空串， 至少要匹配一个字符）
"\" 用来转义特殊符号。如 www\.google\.com 中的点号就不再表示通配符。
捕获组：圆括号 "( )" 包围的部分即为捕获组。 E.g. www\.(.+)\.com 会匹配各 .com 域名，并把去掉 "www." 前缀与 ".com" 后缀的部分存入第 1 组。

More info about regular expressions: Wikipedia, Mozilla Developer Network

日期占位符

在目标路径中加入占位符 date，即可按日期/时间归类。 几个常用示例：

  • ${date} → 2018-11-18
  • ${date:YYYY} → 2018
  • ${date:YYYY, MMMM} → 2018, November
  • ${date:YYYY.MM.DD} → 2018.11.18
  • ${date:YYYY.MM.DD_HH-mm-ss} → 2018.11.18_16-38-08

日期格式详见 moment.js documentation.

自定义文件扩展名

受 Chrome API 限制，无法为已知 MIME 类型指定其他扩展名。 变通办法：用第三方扩展改写下载地址的响应头， 把 Content-Type 改成生僻 MIME 类型（如 application/x-unknown-mime-type）， 之后即可在目标路径中写自定义扩展名。
